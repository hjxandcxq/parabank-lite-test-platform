## 二、业务规则

### 2.1 登录模块规则

1. 用户名必填，长度 6 ~ 20 位
2. 用户名只允许字母、数字、下划线
3. 密码必填，长度 6 ~ 20 位
4. 密码只允许字母、数字和字符 @ # $ . _
5. 用户名必须已在系统中注册
6. 密码必须与注册时一致
7. 用户名或密码任一为空时，不允许提交
8. 验证码必填，4 位字母数字，不区分大小写，有效期 120 秒且一次性使用

### 2.2 注册模块规则

1. 用户名必填，长度 6 ~ 20 位
2. 用户名只允许字母、数字、下划线
3. 用户名必须全局唯一，不能与已有账号重复
4. 密码必填，长度 6 ~ 20 位
5. 密码必须同时包含字母和数字，且只允许字母、数字和字符 @ # $ . _
6. 确认密码必须与密码保持一致

### 2.3 转账模块规则

1. 转账金额必填
2. 金额范围 0.01 ~ 50000.00 元
3. 金额最多保留 2 位小数
4. 金额只能包含数字和一个小数点
5. 源账户余额必须 ≥ 转账金额
6. 源账户和目标账户不能相同
7. 目标账户必须存在

### 转账账户定义（文档二节末原文）

转账测试中用字母 A、B、C、D 表示账户：账户 A 为正常源账户（初始余额 100000.00 元）；账户 B 为正常目标账户（初始余额 0.00 元）；账户 C 为余额不足专用账户（初始余额 100.00 元）；账户 D 表示不存在的目标账户。每次执行用例前测试数据恢复至上述初始状态。所有转账用例统一使用已注册账号 alice01 / Pass123 登录。

### 落地口径（相对文档的偏差）

| 模块 | 规则 | 落地口径 |
|------|------|----------|

## 九、一致性校验

```bash
python check_consistency.py --online   # 用例表 / 被测系统 / 平台库 / pytest / 执行结果 / 文档
python gen_case_doc.py                # 用例表变更后重新生成本文档
```

被测系统、平台库、pytest 套件、本文件均由 `testcase_spec.py` 派生，任何一处改动都会被校验脚本发现。其中"平台执行结果"一项会比对三个套件最近一次执行的实际失败集合与缺陷清单（4 条），多失败或少失败都会报错。
