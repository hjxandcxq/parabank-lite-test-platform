# ParaBank 测试平台 — 数据库设计

## 表 1：test_suites（测试套件）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| name | TEXT | 套件名称，如"登录模块测试" |
| module | TEXT | 归属模块，如 "登录/转账/注册" |
| path | TEXT | pytest 项目相对路径 |
| description | TEXT | 描述 |
| enabled | INTEGER | 1=启用 0=禁用 |
| created_at | TIMESTAMP | 创建时间 |

## 表 2：test_cases（测试用例）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| suite_id | INTEGER FK | 所属套件 |
| case_code | TEXT | 用例编号，如 TC-LOGIN-001 |
| name | TEXT | 用例名称 |
| category | TEXT | 分类：功能/运营/UI/异常 |
| priority | TEXT | 优先级：P0/P1/P2 |
| steps | TEXT | 步骤（JSON 数组） |
| expected | TEXT | 预期结果 |
| pytest_node | TEXT | pytest 节点 ID，如 test_login.py::test_login[LOGIN_001] |
| created_at | TIMESTAMP | 创建时间 |

## 表 3：suite_runs（套件执行记录）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| suite_id | INTEGER FK | 所属套件 |
| status | TEXT | RUNNING / PASS / FAIL / ERROR |
| total | INTEGER | 用例总数 |
| passed | INTEGER | 通过数 |
| failed | INTEGER | 失败数 |
| error | INTEGER | 错误数 |
| skipped | INTEGER | 跳过数 |
| duration_ms | INTEGER | 总耗时 |
| triggered_by | TEXT | 触发者 |
| started_at | TIMESTAMP | 开始时间 |
| finished_at | TIMESTAMP | 结束时间 |

## 表 4：test_results（测试结果明细）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| run_id | INTEGER FK | 所属执行记录 |
| case_id | INTEGER FK | 用例 ID（可空） |
| case_name | TEXT | 用例名（冗余，便于展示） |
| status | TEXT | **PASS / FAIL / ERROR / SKIP** |
| duration_ms | INTEGER | 单条耗时 |
| actual_result | TEXT | 手工验证台观察到的**系统实际返回**（"结果明细"的"实际提示"列） |
| failure_reason | TEXT | **失败原因（一行摘要）** |
| traceback | TEXT | **完整异常堆栈** |
| screenshot_path | TEXT | 失败截图路径 |
| executed_at | TIMESTAMP | 执行时间 |

### 状态定义

| 状态 | 含义 | 触发条件 |
|------|------|---------|
| PASS | 通过 | 断言全部成功 |
| FAIL | 失败 | 断言失败（业务不符合预期） |
| ERROR | 错误 | 代码异常、元素找不到、超时等 |
| SKIP | 跳过 | 标记 skip 或前置条件不满足 |

### 失败原因分类（failure_reason 前缀）

- `ASSERT_` 断言失败，如 `ASSERT_期望文本"Transfer Complete"未出现`
- `TIMEOUT_` 超时，如 `TIMEOUT_等待元素amount超30s`
- `NOELEMENT_` 元素未找到
- `NETWORK_` 网络/连接错误
- `DRIVER_` 浏览器驱动异常
- `UNKNOWN_` 未分类

## 表 5：users（系统用户）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| username | TEXT UNIQUE | 用户名 |
| display_name | TEXT | 显示名 |
| role | TEXT | admin / tester / viewer |
| created_at | TIMESTAMP | 创建时间 |

## 索引

- `test_results(run_id)`
- `test_results(status)`
- `suite_runs(suite_id, started_at)`
- `test_cases(suite_id)`

## 表 6：meta（平台元数据）

| 字段 | 类型 | 说明 |
|------|------|------|
| key | TEXT PK | 键名，当前仅 `seed_version` |
| value | TEXT | 键值 |

用途：记录套件/用例表的 seed 版本。`app.py` 启动时若库中版本与
`SEED_VERSION` 不一致，就从 `testcase_spec.py` 重建 `test_suites` 与 `test_cases`。

## 数据来源与预置数据

- `test_suites` / `test_cases`：由 `testcase_spec.py` 生成（60 条用例），
  请勿手工改库；改用例后把 `app.py` 的 `SEED_VERSION` +1 并重新生成文档
- `pb_users` / `pb_accounts`：被测系统预置演示数据，见 `parabank_lite.PRESET_USERS`
  （alice01 持有 A/B/C＝10001/10002/10003，admin 不持有账户），
  每次套件执行前由 `parabank_lite.reset_demo_data()` 复位
